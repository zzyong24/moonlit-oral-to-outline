# 月明·口述成纲

把你讲过的想法整理成可确认的大纲，确认方向以后，再补证据、写成稿。

适合已经有经验、观点或实现过程，想先说出来再组织成文章或视频的人。你提供原始口述或转写，Agent 帮你理顺主线，保留你的经历和口吻。

## 你会得到什么

| 你现在有 | 这一步交付 |
| --- | --- |
| 一段口述、转写或零散讲解 | 一份有主线、章节与观众收益的大纲 |
| 想演示的操作，但还没安排顺序 | 演示动作、预期观察和时间分配 |
| 说过但还没核验的判断 | 明确标出的证据缺口 |
| 已确认的大纲 | 按需研究，以及交给视频或文章 Skill 的写作材料 |

先把“这次要讲什么”定下来，再投入调研和制作。

## 看一个使用示意

下面是说明交互方式的虚构例子，不是真实任务的运行记录。

> 我刚做了一个会议记录整理流程。开始只有转写，后来加了负责人和截止时间，但我不确定效果该怎么讲。帮我整理成五分钟视频大纲。

大纲可以围绕三个问题展开：

1. 原来拿到转写以后，还需要手工做什么？
2. 新流程怎样把讨论整理为可执行的待办？
3. 哪些结果已经验证，哪些仍需要人工检查？

每一段同时写清楚要展示的材料和还缺的证据。你可以直接改大纲，也可以说“按这个版本继续”。确认之后才进入后续研究和写作。

## 开始使用

将完整的 `moonlit-oral-to-outline` 目录交给支持本地 Skill 的 Agent 安装，保留目录内的 `SKILL.md` 和 `assets/`。已有同名安装时先检查版本与差异；有版本锁的工程沿用自己的升级机制。

让 Agent 安装：

```text
请安装这个 Skill：https://github.com/zzyong24/moonlit-oral-to-outline
```

或者使用 Skills CLI：

```bash
npx skills add zzyong24/moonlit-oral-to-outline
```

安装后直接说：

```text
用 moonlit-oral-to-outline 整理下面这段口述。
先给我大纲，保留我的主张和经历，把需要补证据的地方标出来。
```

```text
把这段讲解整理成五分钟教学视频的大纲。
每一段写清楚讲什么、演示什么、观众能看到什么结果。
```

```text
按刚才确认的大纲继续，补齐证据，再交给文章 Skill 写稿。
```

## 配置与配套能力

大纲阶段无需额外配置、API Key 或脚本环境。输入是文本口述或已有转写；这个 Skill 不提供音频转写服务。

| 阶段 | 需要的能力 |
| --- | --- |
| 整理、调整和确认大纲 | 能读取 Skill、处理文本及保存工作区文件的 Agent |
| 确认后补证据 | 按研究问题使用网页、源码或实际操作工具 |
| 写视频脚本 | [moonlit-video-script](https://github.com/zzyong24/moonlit-video-script) |
| 写公众号文章 | [moonlit-wechat-article](https://github.com/zzyong24/moonlit-wechat-article) |
| 成稿后审读表达 | [moonlit-de-ai-perception](https://github.com/zzyong24/moonlit-de-ai-perception) |

后续 Skill 按任务选择安装。缺少写作依赖时，仍可交付已有大纲和证据。依赖通过当前环境激活的名称查找，无需把仓库放在相邻目录。

## 内容与数据

原始口述、大纲、证据和成稿保存在使用方工作区。已有作品继续使用原作品编号；这些产物不写进 Skill 安装目录。

输入会由你当前使用的 Agent 处理。整理大纲不额外调用第三方评分服务；确认后的研究按所选工具的权限和数据边界执行。源码核验、实际运行和作者口述会分别标记，不把预期结果写成已经成功。

## 使用边界

本 Skill 处理“我先说一遍，你帮我整理”的任务。选题采集、音频转写、画图、录屏、成片与平台发布交给对应能力。

核心流程见 [SKILL.md](SKILL.md)，大纲格式见 [模板](assets/outline-template.md)。外部服务与跨宿主行为需要在使用者环境中验证。
