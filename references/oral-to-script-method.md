# 口述成稿：六步手艺

目标：把作者说过的话，变成**作者自己能直接对着提词器念、念出来还像他本人**的短视频口播稿。忠实的是意思和口吻，不是字数（信达雅规则见 `moonlit-content-engine/references/editorial-contract.md`，本文件只写怎么做）。

一句话标准：**作者念的时候不卡口，观众听的时候不走神，作者回看时认得出“这是我说的”。**

## 0. 先定两件事

| 问题 | 默认 | 什么时候换 |
| --- | --- | --- |
| 模式 | **润色**：保留原话、原顺序为主，修剪重排 | 用户说“重写/换个讲法/你来写”才用**重写**：可换句子，仍不换观点、事实和数字 |
| 时长 | 按口述信息量估，短视频默认 60–180 秒 | 用户给了时长就按用户的；超出时先砍题外话，再砍次要例子，最后才压句子 |

## 1. 听：先把口述拆成素材块，再动笔

逐段读口述，给每一块标类型和原文位置：

- **事**：发生了什么（时间、人物、动作、结果）
- **数**：数字、价格、时长、次数
- **判**：作者的判断、结论、态度
- **法**：怎么做的步骤
- **情**：情绪、玩笑、吐槽、自嘲
- **岔**：和本期主线无关的题外话

然后做两件事：

1. **找主线**：作者最想让观众带走的那一句是什么？优先用作者原话里的那句（常出现在结尾或“我觉得……”后面）。找不到就从“判”里选最具体的一条，写在骨架第一行让作者确认。
2. **列锁定清单 [锁]**：作者的主张、亲历、所有数字、态度词、有意的口头表达和梗、作者自己说的钩子和钉子句。锁定内容可以挪位置、可以拆句，**不能改意思、不能换数字、不能删掉**（作者要求删除的除外）。

「岔」不删，放进骨架的“本期不讲”，作者可能想留到下一期。

## 2. 剪：只剪噪音，不剪肉

| 剪掉 | 怎么剪 |
| --- | --- |
| 口头禅：嗯、啊、然后、就是说、那个、其实、对吧 | 删；但“对吧？”在真的问观众时保留 |
| 自我修正：“一个礼拜吧，不对，应该是五天” | 只留最后的说法：“五天” |
| 重复：同一个意思说了两遍 | 留更具体的那一遍 |
| 绕路铺垫：“我先说一下背景啊”“这个事情是这样的” | 删，直接说事 |
| 空连接：“然后呢”“接下来就是” | 换成有逻辑的连接（所以、结果、问题是）或直接断句 |

**不剪**：例子、数字、情绪、玩笑、作者的口头禅式金句（如果那就是他的风格）、回答观众疑问的短句。剪完对照锁定清单逐条打勾。

## 3. 排：作者顺序能用就不动

先试作者原顺序。原顺序有以下问题才重排：

- 结果/最有意思的东西藏在最后 → 提一句到开头当钩子，原位置保留展开
- 先讲方法后讲问题 → 换成先问题后方法
- 两件事交叉着讲 → 分开讲完一件再讲另一件

短视频的默认骨架（只是参照，不是模板）：

1. **钩子**（≤3 秒，1–2 句）：从锁定清单里选，按 `writing-toolkit.md` 钩子选型挑一种，不叠加
2. **起因**（1–2 句）：观众得知道“为什么要做这件事”
3. **过程**：按时间或按问题推进，每段只做一件事
4. **转折/取舍**：卡在哪、怎么发现的、怎么改的（口述里有才写）
5. **判断或方法**：作者的结论，或观众能照做的那一步
6. **收尾**：用作者的钉子句、感受或下一步收住；没有就自然结束，不硬加 CTA

## 4. 补：只补“桥”和“解释”，不补“内容”

可以补：

- **桥句**：两段之间观众会问“所以呢/为什么”的地方，补一句承接（“后来我加了一步：”）。标 `[补:承接]`
- **一句话解释**：术语、产品名第一次出现时，用观众听得懂的话解释一次。标 `[补:解释]`
- **加法招数**：按 `moonlit-business-copywriter/references/writing-toolkit.md` 选 2–3 招（具体化、数字锚点、动作化、比喻、问句、节奏）。比喻优先与本期母意象同源。标 `[补:招数名]`

不可以补：作者没讲过的经历、案例、数字、效果、对比数据；“据统计”“研究表明”；规避话术（待核验、以实际为准、仅供参考）。

补充的字数不超过全稿的 25%。超过说明在替作者写新内容，回到骨架问作者。

## 5. 读：写给耳朵

规则见 `writing-toolkit.md` §6，这里只列口述成稿最常犯的四个：

1. **长句没拆**：口述里一口气的长句，书面看着顺，念出来断气。单句 ≤20 字，最长 30 字。
2. **重音埋在句中**：把数字、结果、关键名词挪到句尾。
3. **书面词替换了口语**：作者说“搞错”，稿子写成“出现偏差” → 改回“搞错”。作者的用词就是他的口吻。
4. **连续三句一样长**：中间插一句 4–8 字的短句。

自检：从头到尾小声念一遍，每处卡口都改。

## 6. 标：交付提词器版

按 `assets/script-template.md` 输出：

- 一句一行，一个镜头一段（空行分段）
- 重音用 **加粗**（剪辑字幕跳色和动效触发都落在这里）
- 气口用 `／`（念的时候停半拍，也是给画面出图的点）
- 需要画面的地方行尾写 `[画面: 具体看到什么]`，交给 `moonlit-video-script` 做镜次表；只写可拍/可做的东西
- 补充内容标 `[补:…]`，锁定原话可标 `[锁]`，作者审稿时一眼看出哪些是他的、哪些是加的

交付前跑 `python3 scripts/check_oral_script.py --oral 口述.txt --script 口播稿.md`。error 必须改或在交付说明里写理由；warn 列给作者，由作者决定。

## 7. 回炉：让 Skill 越用越像作者

作者改过稿或录完实录后：

1. 对比“我交付的稿”和“作者最终念的版本”，只看有规律的差异：他总是把哪类词改回去、总是删掉哪类补充、总是加回哪类口头表达。
2. 每条规律写成一条候选规则（“作者把‘出现偏差’改回‘搞错’：书面词替换口语时一律用原词”），附原句证据。
3. 交给作者确认后，写入 `moonlit-content-engine/references/feedback-ledger.md` 的 W（文字）区；具体私人习惯写工作区的 `spoken-style-profile.json`，不写进可安装 Skill。
4. 卡壳、重录、ASR 识别错误不算文风。
